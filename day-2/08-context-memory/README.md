# Module 8 — Context และ memory

> ⏱ ~30 นาที · 🎯 ส่งงานกลับ leader แบบสั้น และรู้ว่า memory คนละอย่างกับ CLAUDE.md · Hand back a short summary, and keep project memory separate from CLAUDE.md.

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ทำไมรายงานของเอเจนต์ย่อยถึงต้องสั้น? คำตอบอยู่ที่เส้นทางของข้อมูล: เอเจนต์ย่อยไม่เห็นบทสนทนาหลักของคุณเลย — มันเห็นแค่ข้อความมอบงานที่ leader เขียนส่งให้ มันอ่านไฟล์เองในโลกของตัว แล้วพอทำเสร็จ **ทุกคำที่มันส่งกลับมาจะถูกใส่เข้าไปในบทสนทนาของ leader และคุณ** — รายงานยาวหลายฉบับกลับมาพร้อมกันเท่ากับเติมถังน้ำของ leader ด้วยมือคุณเอง

สิ่งที่ควรส่งกลับจึงมีสามอย่างเท่านั้น: คำตอบของโจทย์สั้น ๆ, หลักฐานที่ชี้ตรง (`file:line` หรือชื่อคอลัมน์), และรายการสิ่งที่มันยังตรวจไม่ได้ — ข้อความอื่นคือราคาที่จ่ายไปเปล่า

อีกเรื่องที่ต้องแยกให้ออกคือ **CLAUDE.md กับ `memory` คนละเรื่องกัน**: CLAUDE.md คือกติกาที่**คุณเขียนไว้ในไฟล์** คงที่จนกว่าจะแก้ ส่วน memory คือสิ่งที่เอเจนต์**จดเองระหว่างทำงาน**และพกไปเซสชันถัดไป — ของที่ควรอยู่ไฟล์ก็อยู่ไฟล์ อย่าให้เอเจนต์จดสิ่งที่เปลี่ยนทุกวันไว้เป็นความจำ

> EN: Subagents see the task, not your whole chat. Memory is learned state. CLAUDE.md is written policy.

## Concept / เนื้อหา

สามกฎของบทนี้ (จำสามข้อพอ):

1. เอเจนต์ย่อยไม่เห็นแชทหลัก — เห็นแค่งานที่ถูกส่งให้
2. อย่าส่งรายงานยาวหลายฉบับกลับ leader พร้อมกัน — ทุกคำคือ token ของ leader
3. บทสนทนายิ่งยาวไม่ได้แปลว่า Claude ทำงานดีขึ้น — ยาวเกินคือสัญญาณว่าควรส่งงานเป็นเอเจนต์ย่อย

ฟิลด์ `memory` ใน frontmatter มีสามขอบเขตให้เลือก (แผ่นอ้างอิง):

| ค่า | จำอะไร |
|---|---|
| `user` | ข้ามโปรเจกต์ ของคนนี้ |
| `project` | โปรเจกต์นี้ แชร์ในทีม |
| `local` | โปรเจกต์นี้ เครื่องนี้ |

ข้อตกลงของแอปเราที่ใช้ซ้อม: "ใช้ Node `http` ล้วน ห้ามเสนอ Express ถ้าไม่ได้ขอ" — ข้อนี้มีอยู่แล้วใน `CLAUDE.md` แล็บนี้จึง**ตั้งใจ**ให้เอเจนต์จดซ้ำใน memory เพื่อดูว่ามันพกข้อตกลงไปข้ามเซสชันได้จริงไหม ข้อจำกัดต้องบอกตรง ๆ: การจำข้ามเซสชันของฟิลด์ `memory` ยังไม่เคยถูกทดสอบจริงในชุดนี้ — ถ้าเปิดเซสชันใหม่แล้วมันยังอ้างข้อตกลง จดผลนั้นไว้ ถ้าไม่อ้างก็จดผลนั้นไว้เช่นกัน แล้วไปต่อที่ Workshop 5 ได้

## ลงมือทำตามลำดับ

```bash
claude
```

1. เปิดไฟล์ `.claude/agents/data-researcher.md` แก้ผ่าน TUI โดยเพิ่มบรรทัด `memory: project` ใน frontmatter (อย่าลืมว่าการแก้ไฟล์ `.claude/**` ต้องกดอนุมัติใน TUI)

2. วาง prompt จากหัวข้อถัดไป — เอเจนต์ต้องจดข้อตกลงไว้ใน memory ของตัวเอง

3. ออกจากเซสชัน (`/exit`) แล้วเปิดใหม่ (`claude`) — ถามคำถามที่ลองข้อตกลง:

```text
ขอแนะนำวิธีทำแอปนี้ให้ดีขึ้นหน่อย
```

4. ผลที่ต้องสังเกต: เอเจนต์ควรยึดข้อตกลง (ไม่เสนอ Express) — จดผลว่า "อ้างได้" หรือ "อ้างไม่ได้" ไว้ในบันทึกของคุณ

## Prompt pattern — เลือกใช้อย่างใดอย่างหนึ่ง

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Ask the data-researcher subagent to remember this project note: Sales Insight uses plain Node http and no dependencies. Do not suggest Express unless asked.
```

**เวอร์ชันไทย (ใช้ได้เต็มที่):**

```text
ให้ subagent data-researcher จดไว้ว่า Sales Insight ใช้ Node http ล้วน ไม่มี dependency ห้ามแนะนำ Express ถ้าไม่ได้ขอ
```

> 📚 **ทำไมแนะนำ EN:** ข้อความที่จดจะถูกอ้างในเซสชันใหม่ — ภาษาอังกฤษสั้นกว่าและคงถ้อยคำเดียวกับกติกาเดิมใน CLAUDE.md TH ทำงานเหมือนกันทุกอย่าง

| ส่วน | หน้าที่ |
|---|---|
| ชื่อเอเจนต์ | ไม่ให้ leader จดเองมั่ว |
| ประโยคห้าม Express | ของที่เอาไปถามซ้ำในเซสชันใหม่ |
| project note | บอกว่านี่คือการจด memory ไม่ใช่ให้แก้โค้ด |

## Common pitfalls / กับดัก

- ให้ทุกเอเจนต์มี memory ทุกขอบเขต — ของเก่าโผล่มาทุกงาน memory กลายเป็นขยะที่ต้องจ่าย token รับ
- ใส่ตัวเลขยอดขายที่เปลี่ยนทุกไฟล์ลง CLAUDE.md — ขัดกับสถานะจริงเร็วมาก ของที่เปลี่ยนให้อยู่ในไฟล์ข้อมูล
- ส่ง CSV ทั้งไฟล์กลับ leader — ถังของ leader เต็มในรอบเดียว อ่านเลขที่สรุปเท่านั้น
- ใช้ `claude -p` แล้วแก้ frontmatter ไม่ได้ — `.claude/**` ถูกปฏิเสธ แก้ผ่าน TUI
- ตั้ง `--max-turns` ต่ำ — ยังไม่ทันจด รอบจบไปแล้ว
- สับสนพอร์ต 3000 กับงานความจำ — รอบนี้ไม่ต้องเปิดเซิร์ฟเวอร์เลย
