# Module 10 — Context และ memory

> ⏱ ~30 นาที · 🎯 ส่งงานกลับ leader แบบสั้น · รู้ว่า memory คนละอย่างกับ CLAUDE.md · เปิด memory ให้สองตัวที่ได้ประโยชน์ (`data-researcher` + `qa`) แล้วเทียบกับตัวที่ไม่มี

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ทำไมรายงานของเอเจนต์ย่อยถึงต้องสั้น? คำตอบอยู่ที่เส้นทางของข้อมูล: เอเจนต์ย่อยไม่เห็นบทสนทนาหลักของคุณเลย — มันเห็นแค่ข้อความมอบงานที่ leader เขียนส่งให้ มันอ่านไฟล์เองในโลกของตัว แล้วพอทำเสร็จ **ทุกคำที่มันส่งกลับมาจะถูกใส่เข้าไปในบทสนทนาของ leader และคุณ** — รายงานยาวหลายฉบับกลับมาพร้อมกันเท่ากับเติมถังน้ำของ leader ด้วยมือคุณเอง

สิ่งที่ควรส่งกลับจึงมีสามอย่างเท่านั้น: คำตอบของโจทย์สั้น ๆ, หลักฐานที่ชี้ตรง (`file:line` หรือชื่อคอลัมน์), และรายการสิ่งที่มันยังตรวจไม่ได้ — ข้อความอื่นคือราคาที่จ่ายไปเปล่า

อีกเรื่องที่ต้องแยกให้ออกคือ **CLAUDE.md กับ `memory` คนละเรื่องกัน**: CLAUDE.md คือกติกาที่**คุณเขียนไว้ในไฟล์** คงที่จนกว่าจะแก้ ส่วน memory คือสิ่งที่เอเจนต์**จดเองระหว่างทำงาน**และพกไปเซสชันถัดไป — ของที่ควรอยู่ไฟล์ก็อยู่ไฟล์ อย่าให้เอเจนต์จดสิ่งที่เปลี่ยนทุกวันไว้เป็นความจำ

> EN: Subagents see the task, not your whole chat. Memory is learned state. CLAUDE.md is written policy.

## Concept / เนื้อหา

สามกฎของบทนี้ (จำสามข้อพอ):

1. เอเจนต์ย่อยไม่เห็นแชทหลัก — เห็นแค่งานที่ถูกส่งให้
2. อย่าส่งรายงานยาวหลายฉบับกลับ leader พร้อมกัน — ทุกคำคือ token ของ leader
3. บทสนทนายิ่งยาวไม่ได้แปลว่า Claude ทำงานดีขึ้น — ยาวเกินคือสัญญาณว่าควรส่งงานเป็นเอเจนต์ย่อย

ฟิลด์ `memory` ใน frontmatter มีสามขอบเขตให้เลือก (แผ่นอ้างอิง):

| ค่า | จำอะไร |
|---|---|
| `user` | ข้ามโปรเจกต์ ของคนนี้ |
| `project` | โปรเจกต์นี้ แชร์ในทีม |
| `local` | โปรเจกต์นี้ เครื่องนี้ |

### แล็บนี้เปิด memory สองตัว — ให้เห็นประโยชน์คนละแบบ

**memory เป็นของเอเจนต์รายตัว** — ไม่ใช่สวิตช์ทั้งโปรเจกต์ · เปิดที่ไฟล์ไหน ตัวนั้นถึงจดและพกความจำ

| ของ | ใครได้ | ใช้เมื่อ |
|---|---|---|
| `CLAUDE.md` | **ทุก**เอเจนต์ในโฟลเดอร์ | กติกาคงที่ที่ทีมต้องยึดเหมือนกัน |
| `memory: project` บนเอเจนต์ | **เฉพาะ**ตัวนั้น | นิสัย/วิธีของบทบาทที่พกข้ามเซสชัน |

ในแล็บผู้เรียนเปิดให้ **สองตัวที่ได้ประโยชน์ชัด** แล้วเทียบกับตัวที่ไม่มี:

| ตัว | มี memory? | โน้ตที่จด | ผู้เรียนเห็นอะไร |
|---|---|---|---|
| `data-researcher` | ใช่ | ไม่แนะนำ Express / Node http ล้วน | จำกติกาสแต็กข้ามเซสชัน |
| `qa` | ใช่ | รีโปรดิวส์ก่อนเขียนรายงาน · ไม่เชื่อคำบอก | จำ**วิธีพิสูจน์**คนละเรื่องกับสแต็ก |
| `developer` | ไม่ | — | ตัวเทียบ — memory ไม่ไหลมาให้เอง |

### ใครสมควรมี persistent memory ในทีมคอร์สนี้

| เอเจนต์ | แนะนำ | จำอะไรได้มีประโยชน์ | อย่าให้จำ |
|---|---|---|---|
| `data-researcher` | **มี** (`project`) — แล็บนี้ | กติกาข้อมูล/สแต็ก · SQL ที่ใช้แล้วเวิร์ก | ยอดรวมล่าสุด (อ่าน CSV/MCP ใหม่) |
| `qa` | **มี** (`project`) — แล็บนี้ | วิธีรีโปรดิวส์ · “ไม่เชื่อคำบอก” | ผล gate รอบล่าสุด (รันใหม่) |
| `release-manager` | มีได้ (Stretch) | จุดพลาดตอนปล่อย | เช็คลิสต์เต็ม — เป็นงาน **skill** |
| `planner` | บางที | สไตล์แผนซ้ำ | สเปกปัจจุบัน — อ่านไฟล์ |
| `developer` | **ไม่ใส่เป็นค่าเริ่ม** | — | บั๊กรอบก่อน — อ่านรายงาน/แผน |
| `writer` | **ไม่ใส่** | — | ตัวเลขรอบก่อน — อ่าน API/CSV |

เกณฑ์สั้น ๆ: **เรียนรู้ “วิธีทำงานซ้ำ” ได้ → ใส่ memory** · **ต้องยึดของส่งล่าสุดบนดิสก์ → อย่าใส่**

> 📚 **กฎง่าย ๆ:** กติกาทีม → `CLAUDE.md` · นิสัยบทบาท → `memory` เฉพาะตัวที่สมควร · ของส่งรอบนี้ → ไฟล์ handoff · แล็บนี้สองตัวพอ — อย่าเปิดทุกตัว

ข้อจำกัด: การจำข้ามเซสชันยังไม่ถูกล็อกในสคริปต์ของคอร์ส — จดผลแต่ละตัวว่าอ้างโน้ตได้หรือไม่ แล้วไปต่อ Workshop 8 ได้

## ลงมือทำตามลำดับ

```bash
claude
```

1. เพิ่ม `memory: project` ให้ **ทั้ง** `data-researcher` และ `qa` (ข้อความคัดลอกอยู่ที่ [LAB.md](LAB.md)) — **ไม่ใส่** `developer`
2. รีสตาร์ท TUI → ให้แต่ละตัวจดโน้ตคนละแบบ
3. `/exit` แล้วเปิดใหม่ → ถาม `@data-researcher` · `@qa` · `@developer` ตาม LAB
4. จดผลสามช่อง: researcher อ้างสแต็กได้ไหม · qa พูดถึงรีโปรดิวส์ไหม · developer ไม่พกโน้ตเดียวกัน

## สิ่งที่ prompt ต้องมี (ทบทวน — ข้อความคัดลอกอยู่ที่ [LAB.md](LAB.md))

| ส่วน | หน้าที่ |
|---|---|
| เปิด memory สองไฟล์ | เห็นว่าเป็นรายตัว ไม่ใช่สวิตช์โปรเจกต์ |
| โน้ต researcher ≠ โน้ต qa | คนละประโยชน์ — สแต็ก vs วิธีพิสูจน์ |
| ถาม `@developer` ด้วย | ตัวเทียบว่า memory ไม่แชร์ข้ามบทบาท |

## Common pitfalls / กับดัก

- ให้ทุกเอเจนต์มี memory ทุกขอบเขต — ของเก่าโผล่มาทุกงาน memory กลายเป็นขยะที่ต้องจ่าย token รับ
- ใส่ตัวเลขยอดขายที่เปลี่ยนทุกไฟล์ลง CLAUDE.md — ขัดกับสถานะจริงเร็วมาก ของที่เปลี่ยนให้อยู่ในไฟล์ข้อมูล
- ส่ง CSV ทั้งไฟล์กลับ leader — ถังของ leader เต็มในรอบเดียว อ่านเลขที่สรุปเท่านั้น
- ใช้ `claude -p` แล้วแก้ frontmatter ไม่ได้ — `.claude/**` ถูกปฏิเสธ แก้ผ่าน TUI
- ตั้ง `--max-turns` ต่ำ — ยังไม่ทันจด รอบจบไปแล้ว
- สับสนพอร์ต 3000 กับงานความจำ — รอบนี้ไม่ต้องเปิดเซิร์ฟเวอร์เลย
