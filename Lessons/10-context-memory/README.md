# Module 10 — Context และ memory

> ⏱ ~30 นาที · 🎯 ส่งงานกลับ leader แบบสั้น และรู้ว่า memory คนละอย่างกับ CLAUDE.md · Hand back a short summary, and keep project memory separate from CLAUDE.md.

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ทำไมรายงานของเอเจนต์ย่อยถึงต้องสั้น? คำตอบอยู่ที่เส้นทางของข้อมูล: เอเจนต์ย่อยไม่เห็นบทสนทนาหลักของคุณเลย — มันเห็นแค่ข้อความมอบงานที่ leader เขียนส่งให้ มันอ่านไฟล์เองในโลกของตัว แล้วพอทำเสร็จ **ทุกคำที่มันส่งกลับมาจะถูกใส่เข้าไปในบทสนทนาของ leader และคุณ** — รายงานยาวหลายฉบับกลับมาพร้อมกันเท่ากับเติมถังน้ำของ leader ด้วยมือคุณเอง

สิ่งที่ควรส่งกลับจึงมีสามอย่างเท่านั้น: คำตอบของโจทย์สั้น ๆ, หลักฐานที่ชี้ตรง (`file:line` หรือชื่อคอลัมน์), และรายการสิ่งที่มันยังตรวจไม่ได้ — ข้อความอื่นคือราคาที่จ่ายไปเปล่า

อีกเรื่องที่ต้องแยกให้ออกคือ **CLAUDE.md กับ `memory` คนละเรื่องกัน**: CLAUDE.md คือกติกาที่**คุณเขียนไว้ในไฟล์** คงที่จนกว่าจะแก้ ส่วน memory คือสิ่งที่เอเจนต์**จดเองระหว่างทำงาน**และพกไปเซสชันถัดไป — ของที่ควรอยู่ไฟล์ก็อยู่ไฟล์ อย่าให้เอเจนต์จดสิ่งที่เปลี่ยนทุกวันไว้เป็นความจำ

> EN: Subagents see the task, not your whole chat. Memory is learned state. CLAUDE.md is written policy.

## Concept / เนื้อหา

สามกฎของบทนี้ (จำสามข้อพอ):

1. เอเจนต์ย่อยไม่เห็นแชทหลัก — เห็นแค่งานที่ถูกส่งให้
2. อย่าส่งรายงานยาวหลายฉบับกลับ leader พร้อมกัน — ทุกคำคือ token ของ leader
3. บทสนทนายิ่งยาวไม่ได้แปลว่า Claude ทำงานดีขึ้น — ยาวเกินคือสัญญาณว่าควรส่งงานเป็นเอเจนต์ย่อย

ฟิลด์ `memory` ใน frontmatter มีสามขอบเขตให้เลือก (แผ่นอ้างอิง):

| ค่า | จำอะไร |
|---|---|
| `user` | ข้ามโปรเจกต์ ของคนนี้ |
| `project` | โปรเจกต์นี้ แชร์ในทีม |
| `local` | โปรเจกต์นี้ เครื่องนี้ |

### ทำไมแล็บนี้ใส่ memory แค่ `data-researcher` ตัวเดียว

**memory เป็นของเอเจนต์รายตัว** — ไม่ใช่สวิตช์ทั้งโปรเจกต์ · เปิดที่ไฟล์ไหน ตัวนั้นถึงจดและพกความจำ

| ของ | ใครได้ | ใช้เมื่อ |
|---|---|---|
| `CLAUDE.md` | **ทุก**เอเจนต์ในโฟลเดอร์ | กติกาคงที่ที่ทีมต้องยึดเหมือนกัน (เช่น ห้าม Express) |
| `memory: project` บนเอเจนต์หนึ่งตัว | **เฉพาะ**ตัวนั้น | สิ่งที่ตัวนั้นเรียนรู้ระหว่างงาน แล้วควรพกข้ามเซสชัน |

แล็บสั้นวันนี้ใส่แค่ `data-researcher` เพื่อ**ซ้อมกลไก**และเทียบกับตัวที่ไม่มี memory · ในงานจริง/หลังจบแล็บ มีบทบาทอื่นที่**สมควร**มี persistent memory ด้วย — คนละเรื่องกับ “เปิดทุกตัว”

### ใครสมควรมี persistent memory ในทีมคอร์สนี้

| เอเจนต์ | แนะนำ | จำอะไรได้มีประโยชน์ | อย่าให้จำ |
|---|---|---|---|
| `data-researcher` | **มี** (`project`) | กติกาข้อมูล · คอลัมน์/SQL ที่ใช้แล้วเวิร์ก · ห้ามเดายอด | ยอดรวมล่าสุด (ให้อ่าน CSV/MCP ใหม่ทุกครั้ง) |
| `qa` | **มี** (`project`) | วิธีรีโปรดิวส์ที่เคยใช้ · เคสที่พลาดบ่อย · “ไม่เชื่อคำบอก developer” | ผล gate รอบล่าสุดแบบตายตัว (ให้รันใหม่) |
| `release-manager` | **มีได้** (`project` หรือพึ่ง skill) | จุดที่เคยพลาดตอนปล่อย (port ค้าง · health มี `sk-`) | เช็คลิสต์เต็มชุด — นั้นเป็นงานของ **skill** |
| `planner` | **บางที** (`project`) | สไตล์แผนของโปรเจกต์นี้ · ใครรอใครแบบซ้ำ | สเปกฉบับปัจจุบัน — ให้อ่าน `PRODUCT-SPEC` / `TASKS` |
| `developer` | **ไม่ใส่เป็นค่าเริ่ม** | — | บั๊กรอบก่อน / ทางแก้เก่า — ให้อ่าน `QA-REPORT` + แผนใหม่ทุกครั้ง |
| `writer` | **ไม่ใส่** | — | ตัวเลขรอบก่อน — บังคับอ่าน API/`region-capital.csv` เท่านั้น |

เกณฑ์สั้น ๆ: **บทบาทที่เรียนรู้ “วิธีทำงานซ้ำ” ได้ประโยชน์จาก memory** · **บทบาทที่ต้องยึดของส่งล่าสุดบนดิสก์ อย่าให้ memory แย่งซีนจากไฟล์**

> 📚 **กฎง่าย ๆ:** กติกาทีม → `CLAUDE.md` · นิสัย/วิธีของบทบาท → `memory` เฉพาะตัวที่สมควร · ของส่งรอบนี้ → ไฟล์ handoff · อย่าเปิด memory ทุกตัวทุกขอบเขต

ข้อตกลงที่ใช้ซ้อม: "ใช้ Node `http` ล้วน ห้ามเสนอ Express ถ้าไม่ได้ขอ" — มีอยู่แล้วใน `CLAUDE.md` แล็บนี้จึง**ตั้งใจ**ให้เอเจนต์จดซ้ำใน memory เพื่อดูว่ามันพกข้อตกลงไปข้ามเซสชันได้จริงไหม ข้อจำกัดต้องบอกตรง ๆ: การจำข้ามเซสชันของฟิลด์ `memory` ยังไม่เคยถูกล็อกผลในสคริปต์ของคอร์ส — จดผล "อ้างได้ / อ้างไม่ได้" แล้วไปต่อ Workshop 8 ได้

## ลงมือทำตามลำดับ

```bash
claude
```

1. เพิ่ม `memory: project` ใน frontmatter ของ `data-researcher` ผ่าน TUI (ข้อความคัดลอกอยู่ที่ [LAB.md](LAB.md)) แล้วรีสตาร์ทเซสชัน

2. วาง prompt จดข้อตกลงจาก LAB — เอเจนต์ต้องจดไว้ใน memory ของตัวเอง

3. ออกจากเซสชัน (`/exit`) แล้วเปิดใหม่ (`claude`) — ถามคำถามที่ลองข้อตกลง:

```text
ขอแนะนำวิธีทำแอปนี้ให้ดีขึ้นหน่อย
```

4. ผลที่ต้องสังเกต: เอเจนต์ควรยึดข้อตกลง (ไม่เสนอ Express) — จดผลว่า "อ้างได้" หรือ "อ้างไม่ได้" ไว้ในบันทึกของคุณ

## สิ่งที่ prompt ต้องมี (ทบทวน — ข้อความคัดลอกอยู่ที่ [LAB.md](LAB.md))

| ส่วน | หน้าที่ |
|---|---|
| `@data-researcher` | เรียกเอเจนต์ตรง ๆ ไม่ให้ leader จดเองมั่ว |
| ประโยคห้าม Express | ของที่เอาไปถามซ้ำในเซสชันใหม่ |
| project note / จดไว้ว่า | บอกว่านี่คือการจด memory ไม่ใช่ให้แก้โค้ด |

## Common pitfalls / กับดัก

- ให้ทุกเอเจนต์มี memory ทุกขอบเขต — ของเก่าโผล่มาทุกงาน memory กลายเป็นขยะที่ต้องจ่าย token รับ
- ใส่ตัวเลขยอดขายที่เปลี่ยนทุกไฟล์ลง CLAUDE.md — ขัดกับสถานะจริงเร็วมาก ของที่เปลี่ยนให้อยู่ในไฟล์ข้อมูล
- ส่ง CSV ทั้งไฟล์กลับ leader — ถังของ leader เต็มในรอบเดียว อ่านเลขที่สรุปเท่านั้น
- ใช้ `claude -p` แล้วแก้ frontmatter ไม่ได้ — `.claude/**` ถูกปฏิเสธ แก้ผ่าน TUI
- ตั้ง `--max-turns` ต่ำ — ยังไม่ทันจด รอบจบไปแล้ว
- สับสนพอร์ต 3000 กับงานความจำ — รอบนี้ไม่ต้องเปิดเซิร์ฟเวอร์เลย
