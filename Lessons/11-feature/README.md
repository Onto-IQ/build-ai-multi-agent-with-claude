# Module 11 — Feature ของคุณ / Your feature

> ⏱ ~60 นาที · 🎯 เลือก feature จากเมนู 5 แบบ (หรือคิดเองในกรอบเดียวกัน) แล้วสั่งทีม agents สร้างให้ด้วย handoff เป็นไฟล์ · gate ยัง 6/6

ครึ่งชั่วโมง–ชั่วโมงสุดท้ายของแกนวิชาการก่อน Capstone — ผู้เรียน**เลือกโจทย์เอง** แต่ไม่เริ่มจากหน้าว่าง: มีเมนู 5 แบบที่ดึงจากข้อมูลจริง (กิจการจดทะเบียนใหม่) ซึ่ง query ได้หลายมุมอยู่แล้วจาก Workshop 6

> 📚 นี่คือจุดที่คอร์สเปลี่ยนมุม: จาก "ทำตามโจทย์" เป็น "สั่งทีมจากสเปกของตัวเอง" — ทักษะเดียวกับที่จะใช้วันจริงหลังคอร์ส

แบบฝึกหัด (prompt คัดลอก) อยู่ที่ **[LAB.md](LAB.md)** — เกณฑ์ตรวจอยู่ที่ `solutions/w8/FEATURE-CRITERIA.md`

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ข้อมูลชุดนี้ถามได้หลายแบบ: รายจังหวัด รายภาค รายเดือน ทุนสูงสุด คำในวัตถุประสงค์ — ถ้าปล่อยให้คิด feature เองทั้งห้อง บางคนจะใหญ่เกินชั่วโมง บางคนจะเล็กจนไม่เห็น handoff

เลยมี**เมนู 5 แบบ**ให้เลือกหนึ่งข้อ แล้วใส่ประโยคนั้นแทน `<FEATURE>` ใน prompt ของ planner → developer → qa · ทุกแบบใช้ Node ล้วน ไม่แตะ `quality-gate.js` และต้องรอดไปถึง Capstone / deploy

> EN: Pick one of five query-shaped features. File handoffs only. Gate stays 6/6.

## Concept / เนื้อหา

### เมนู Feature ตัวอย่าง (เลือก 1 จาก 5)

| รหัส | Feature | ผู้ใช้เห็นอะไร | ข้อมูล/API ที่มักใช้ | เหมาะเมื่อ |
|---|---|---|---|---|
| **A** | ตารางจังหวัดแบบโต้ตอบ | ตารางจังหวัด + ค้นหา + เรียงคอลัมน์ + เลือกจำนวนแถว (10/20/all) | จังหวัดจากที่อยู่ · ทุน/จำนวน · `GET` สรุปรายจังหวัด | **แนะนำ** — Capstone สเปกมักยึดตารางนี้ต่อ |
| **B** | Top ทุนจดทะเบียน | ตาราง Top 10/20 กิจการตามทุน มีปุ่มสลับจำนวนแถว | `company_name` · `capital` · `GET /api/top-capital` (หรือชื่อในแผน) | อยากโชว์ outlier ทุนสูง |
| **C** | เปรียบเทียบรายเดือน | การ์ดหรือแท่งเปรียบ ม.ค. / ก.พ. / มิ.ย. (จำนวน + ทุน) | `month` · ยอดจาก dataset หรือ MCP | เน้น seasonality ของข้อมูล 2558 |
| **D** | ค้นหาตามวัตถุประสงค์ | ช่องค้นหาคำใน `objective` แล้วได้รายการกิจการสั้น ๆ | `objective` · `company_name` · `GET` ค้นหา | โชว์ text query บนข้อมูลเปิด |
| **E** | Export CSV ตามตัวกรอง | ปุ่มดาวน์โหลด CSV ของสรุปจังหวัดหรือภาคตามตัวกรองบนหน้า | สรุปที่มีอยู่ + `Content-Disposition` / blob ฝั่งเว็บ | เน้น “เอาข้อมูลออกไปใช้ต่อ” |

กฎการเลือก:

1. เลือก**หนึ่ง**รหัส (A–E) หรือผสมเล็กน้อยในขอบเขตเดียวกัน (เช่น A แต่ยังไม่ทำ sort — ตัดได้)
2. เขียนประโยค `<FEATURE>` หนึ่งบรรทัดจากคอลัมน์ “ผู้ใช้เห็นอะไร”
3. ถ้าจะเข้า Capstone แบบลื่นที่สุด → เลือก **A**
4. ห้ามเลือกของที่ต้องมี dependency ใหม่ หรือต้องมีฐานข้อมูลแยกนอกไฟล์ที่มีอยู่

### เกณฑ์กำกับ (ทุกข้อต้องผ่าน)

1. **Deploy ได้จริง** — อยู่ใน build ที่ขึ้น Vercel (Module 13)
2. **Quality gate ยังเขียว** — `npm run gate` exit 0 หลังมี feature
3. **Agents ≥ 2 ตัว + handoff เป็นไฟล์** — planner → `FEATURE-PLAN.md` → developer → qa append `QA-REPORT.md`
4. **ไม่แตะของต้องห้าม** — ห้าม `sk-` · ห้ามแก้ `quality-gate.js` · Node ล้วน

### วงจร handoff

```text
คุณเลือก A–E (หรือประโยคเองในกรอบเดียวกัน)
  → @planner เขียน docs/FEATURE-PLAN.md
  → @developer ทำตามแผน (คง /api/summary · /api/health · /api/notes)
  → คุณรัน npm run gate + เปิดเว็บดูของจริง
  → @qa append ผลรับรองใน docs/QA-REPORT.md
```

## ลำดับในห้อง (ภาพรวม)

1. เปิดเมนู 5 แบบ → เลือก 1 รหัส → เขียนประโยค `<FEATURE>`
2. `@planner` … แทนประโยคนั้น → ได้ `FEATURE-PLAN.md`
3. `@developer` ทำตามแผน → คุณตรวจเว็บ + gate
4. `@qa` รับรอง feature ใน `QA-REPORT.md`
5. จดรหัสที่เลือกไว้ — Capstone จะถามว่า feature รอดไหม

## สิ่งที่ต้องจำ (ทบทวน)

| จุด | ความหมาย |
|---|---|
| เมนู 5 แบบ | ลดสเปกบาน / ให้ทุกคนมี handoff ครบในเวลา |
| A = เส้น Capstone | ตารางจังหวัดโต้ตอบต่อสเปก release ได้ง่าย |
| Query ได้หลายแบบ ≠ ทำทุกแบบ | เลือกหนึ่งมุมของข้อมูล |
| Handoff เป็นไฟล์ | ห้ามจบด้วยแชทอย่างเดียว |
| Gate เขียว | เงื่อนไขเข้า Workshop 9 / deploy |

## Common pitfalls / กับดัก

- เลือกสอง–สามรหัสพร้อมกันแล้วไม่จบชั่วโมง
- สเปกคลุมเครือ (“ทำ dashboard สวย ๆ”) — ต้องมีตาราง/ปุ่ม/endpoint ในประโยค
- แตะ contract ของ `/api/summary` หรือ `/api/health` โดยไม่จำเป็น
- ลืมให้ qa บันทึก — Capstone ไม่มีหลักฐานว่ารับรองแล้ว
- คิดว่าต้องมี MCP ถึงทำ feature ได้ — ใช้ `dataset.csv` / API ที่มีก็พอ
