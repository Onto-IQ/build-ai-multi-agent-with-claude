# Module 4 — เอเจนต์เฉพาะทาง / Specialty agents

> ⏱ ~55 นาที · 🎯 ให้ Claude เขียนไฟล์เอเจนต์นักวิจัยข้อมูลที่อ่านอย่างเดียว แล้วเรียกใช้จนได้หลักฐานแบบ `file:line` · Prompt Claude to add a read-only data researcher and get file:line evidence back.

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ลองนึกภาพ: คุณสั่ง leader ให้ส่งเอเจนต์ย่อยไปสำรวจแอป Registry Insight มันลงมือทันที — โดยไม่รู้เลยว่ากติกาโปรเจกต์นี้เขียนไว้ว่า "งานสำรวจห้ามแก้ไฟล์" ไม่รู้ว่าห้ามแนะนำ Express หรือแพ็กเกจ npm และไม่รู้ด้วยซ้ำว่าเซิร์ฟเวอร์อยู่ไฟล์ไหน มันจึงต้องเดาทุกอย่างเอง และทุกครั้งที่เดาผิด สิ่งที่เราได้กลับมาคือบั๊กจริง ๆ ในโค้ด

ไฟล์ `CLAUDE.md` ที่ราก workshop repo (`C:\dev\multi-agent-workshop`) คือคำตอบของปัญหานี้ — Claude Code หยิบมันขึ้นมาเองทุกครั้งที่เริ่มงาน ทั้งตอนคุณเปิดเซสชันและตอนเอเจนต์ย่อยทุกตัวถูกสร้างขึ้น ไฟล์เดียวจึงเหมือนกฎที่แขวนไว้หน้าประตูโรงงาน: ใครเดินเข้ามาทำงานก็จะได้อ่านก่อนโดยอัตโนมัติ คุณไม่ต้องคอยพิมพ์กติกาซ้ำในทุก prompt

แล้วกฎในไฟล์นี้ถึงมือเอเจนต์ย่อยจริงหรือ? ทีมผู้สอนทดสอบใน Agent Lab โดยสั่งเอเจนต์ย่อยให้ตอบว่า "กฎข้อแรกของโปรเจกต์คืออะไร" โดยห้ามใช้เครื่องมือใด ๆ — ตัวที่ทำงานปกติท่องกฎจาก CLAUDE.md มาได้ถูกต้องทุกคำ ส่วนตัวที่ถูกตั้งค่าให้ไม่อ่านไฟล์นี้ก็ตอบตรง ๆ ว่า "ไม่รู้" แปลว่าไฟล์เดินทางถึงมือมันจริง และหายไปจริงเมื่อเราเอาออก

เอเจนต์เฉพาะทาง (specialty agent) คือขั้นต่อจากนั้น: แทนที่จะอธิบายบทบาทใหม่ทุกครั้งที่สั่งงาน คุณเขียน "ใบบรรยายตำแหน่ง" ไว้เป็นไฟล์เดียวใน `.claude/agents/` — ระบุว่าตำแหน่งนี้ชื่ออะไร เหมาะกับงานแบบไหน แตะเครื่องมืออะไรได้ และควรทำงานบน model ตัวไหน ครั้งต่อไปที่งานตรงประเภท leader จะหยิบตำแหน่งนี้ไปใช้เอง

> EN: `CLAUDE.md` is the project rulebook every subagent reads automatically. A specialty agent is one markdown file in `.claude/agents/` — description routes work, tools fence it, and you verify the file on disk.

## Concept / เนื้อหา

ไฟล์เอเจนต์หนึ่งไฟล์มีสองชั้น ชั้นบนคือ frontmatter — ตัวเลขระหว่างเส้น `---` สองเส้น — ที่บอกระบบว่าตำแหน่งนี้คือใคร ชั้นล่างคือเนื้อหาธรรมดาที่กลายเป็นคำสั่งประจำตัวของเอเจนต์ ในแล็บนี้เราจะสร้างตำแหน่งนักวิจัยข้อมูล `data-researcher` ที่ต้องอ่านอย่างเดียวเสมอ เพราะงานของมันคือตอบคำถามเกี่ยวกับโค้ด ไม่ใช่แก้โค้ด

ฟิลด์สี่ตัวนี้คือสิ่งที่ใช้จริงในแล็บ (ชีตฉบับเต็มอยู่ที่ [reference/frontmatter-cheatsheet.md](../../reference/frontmatter-cheatsheet.md)):

| ฟิลด์ | ค่าของนักวิจัย | เพราะอะไร |
|---|---|---|
| `name` | `data-researcher` | ชื่อไว้เรียก เป็นภาษาอังกฤษ ไม่มีช่องว่าง |
| `description` | ขึ้นต้น `Use proactively` และบอกว่าอ่านอย่างเดียว | **leader ใช้บรรทัดนี้ตัดสินว่าจะส่งงานให้เองหรือไม่** |
| `tools` | `Read, Grep, Glob` | นักวิจัยไม่ต้องเขียนไฟล์ — ไม่ใส่ Write/Edit ไว้ก่อน |
| `model` | `sonnet` | งานอธิบายโค้ดใช้ตัวกลาง เร็วพอ ละเอียดพอ |

เรื่อง `model` จำง่าย ๆ ว่ายิ่งฉลาดยิ่งแพง: `haiku` สำหรับสแกนหาเร็ว, `sonnet` สำหรับอธิบายโค้ด, `opus` สำหรับงานที่พลาดแล้วแพงจริง ชื่อไอดีเต็มเปลี่ยนบ่อย ใช้ชื่อตระกูล (haiku/sonnet/opus) จึงไม่ล้าสมัย

การเรียกใช้มีสามทาง ใช้ตามความมั่นใจ: ทางปกติแค่พูดชื่อไว้ในคำสั่ง ("ให้ data-researcher ตรวจ…") แล้ว leader จัดการส่งเอง · ถ้าอยากบังคับแน่ ๆ ใน TUI ให้พิมพ์ชื่อไฟล์ตรง ๆ · และถ้าอยากให้ทั้งเซสชัน "สวมบท" ตำแหน่งนี้ไปเลย ให้เปิดด้วยตัวเลือก `--agent`

เรื่องสิทธิ์มีกับดักที่ไม่มีป้ายเตือน ที่ควรรู้ก่อนเจอ: `permissionMode` ในไฟล์เอเจนต์มีผลเฉพาะเมื่อคุณเปิด TUI แบบปกติ ถ้าคุณเปิดเซสชันด้วยโหมดยอมรับการแก้ไฟล์อัตโนมัติ เอเจนต์ย่อยจะถูกดึงไปใช้โหมดเดียวกัน ค่าที่คุณเขียนไว้จะถูกเมินโดยไม่เตือน — ทีมผู้สอนเคยทดสอบ: ตัวที่ตั้งไว้ให้เป็นโหมดอ่านอย่างเดียว กลับเขียนไฟล์สำเร็จเมื่อเซสชันหลักเปิดโหมดยอมรับทุกอย่าง (เรื่องเต็มอยู่ใน [reference/failure-modes.md](../../reference/failure-modes.md))

และความกำกวมยังเป็นศัตรูเหมือนเดิม: ลองสั่งแบบ "สร้าง subagent ให้หน่อย" ดู — Claude ไม่รู้ว่าจะสร้างเอเจนต์แบบไหน ไว้ทำอะไร มันจึงใช้รอบทำงานไปกับการเดาจนหมด สุดท้ายคุณจบเซสชันโดยไม่ได้อะไรเลย ทั้งไฟล์เอเจนต์และคำอธิบายว่าเกิดอะไรขึ้น ยิ่งตั้งจำนวนรอบทำงาน (เทิร์น) ไว้น้อย มันยิ่งหมดก่อนจะทันเขียนไฟล์ — สเปกที่สั้น แต่ชัดเจนอย่างในหัวข้อถัดไปจึงเป็นทางเดียวที่ได้ผล

## ลงมือทำตามลำดับ

ทุกขั้นพิมพ์ตามได้เลย ทำในเทอร์มินัล:

```bash
claude
```

1. วาง prompt จากหัวข้อถัดไปลงใน TUI — Claude จะขออนุมัติเขียนไฟล์ `.claude/agents/data-researcher.md` **กดอนุมัติ**
2. เปิดไฟล์ตรวจด้วยตาก่อนเชื่อ:

```bash
cat .claude/agents/data-researcher.md
```

   ต้องเห็น frontmatter ครบสี่ฟิลด์ตามตารางข้างบน และเนื้อหาสามส่วน: วิธีค้น, รูปแบบคำตอบ (Answer / Evidence / Risks), ข้อจำกัดว่าอ่านอย่างเดียว

3. พิสูจน์ว่าใช้งานได้จริง — ปิด TUI แล้วเปิด `claude` ใหม่จากโฟลเดอร์เดิม จึงวางคำสั่งรอบสอง:

```text
ให้ data-researcher อธิบายว่า POST /api/notes ทำอะไร โดยทุกข้ออ้างต้องระบุ server.js:บรรทัด
```

   คำตอบที่ผ่านต้องมีหมายเลขบรรทัดกำกับทุกประเด็น เช่น `server.js:113` — นั่นคือหลักฐานว่าเอเจนต์เปิดไฟล์อ่านเองจริง ไม่ใช่เดาจากชื่อ endpoint

> 📚 **รู้เพิ่ม (ตรวจจริงบน CLI 2.1.310):** ทำไมต้องเปิดเซสชันใหม่ — Claude Code อ่านรายชื่อเอเจนต์จาก `.claude/agents/` ตอนเซสชันเริ่มเท่านั้น ถ้าสั่งเรียกในเซสชันเดิมทันทีที่สร้างไฟล์ จะขึ้น `Agent type 'data-researcher' not found` แม้ไฟล์จะโผล่แล้ว

## Prompt pattern — เลือกใช้อย่างใดอย่างหนึ่ง

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
In this folder, create .claude/agents/data-researcher.md.
Frontmatter exactly: name data-researcher; description starts with "Use proactively" and says the agent is read-only; tools Read, Grep, Glob; model sonnet.
Body sections: Method, Output format with file:line evidence, Constraints that forbid Edit, Write, and Bash.
Do not change server.js or the CSV.
```

**เวอร์ชันไทย (ใช้ได้เต็มที่):**

```text
ในโฟลเดอร์นี้ ให้สร้าง .claude/agents/data-researcher.md
frontmatter ต้องตรงนี้: name เป็น data-researcher; description ขึ้นต้น Use proactively และบอกว่าอ่านอย่างเดียว; tools เป็น Read, Grep, Glob; model เป็น sonnet
เนื้อหามี Method, รูปแบบคำตอบที่อ้าง file:line, และ Constraints ที่ห้าม Edit, Write, Bash
ห้ามแก้ server.js หรือ CSV
```

> 📚 **ทำไมแนะนำ EN:** ฟิลด์ทั้งหมดของไฟล์เอเจนต์ต้องเป็นอังกฤษ (`name`, `tools`, ค่า `model`) — สั่งเป็นอังกฤษจึงตัดขั้นแปลทิ้ง และตัดกับดัก "frontmatter ภาษาไทย" ที่แล็บนี้เตือนไว้ TH ก็ทำได้ (คอร์สทดสอบแล้ว: ค่า machine-readable ออกมาถูกต้องแม้สั่งไทย แต่ body ของ system prompt จะถูกเขียนเป็นอังกฤษตาม default) แต่ต้องเขียนสเปกชัดเป็นพิเศษ

| ส่วน | หน้าที่ |
|---|---|
| ตำแหน่งไฟล์ | กันไม่ให้เขียนผิดที่ |
| ชื่อฟิลด์อังกฤษ | กัน frontmatter ภาษาไทยที่โหลดไม่ได้ |
| ข้อห้ามท้าย prompt | กันไม่ให้ขยายงานไปแก้แอป |

## Common pitfalls / กับดัก

- คุณเขียนไฟล์เองทั้งที่โจทย์คือให้ Claude เขียน — แล็บนี้ฝึก "การสั่ง" ไม่ใช่ "การพิมพ์" ถ้าพิมพ์เอง ทักษะที่จะได้คือทักษะที่คุณมีอยู่แล้ว
- ลองทำใน `claude -p` — การเขียนไฟล์ `.claude/**` ถูกปฏิเสธทุกรูปแบบของ `--allowedTools` เพราะเป็นโฟลเดอร์ตั้งค่าที่ระบบตั้งใจให้คนกดอนุมัติ รอบนี้ทำใน TUI
- `description` ยาวหลายพันตัวอักษร — Claude ต้องพกข้อความนี้ไว้ในบทสนทนาหลักตลอดเวลาเพื่อใช้เลือกส่งงาน เซสชันจึงแพงและช้าขึ้นโดยไม่จำเป็น เขียนสั้นให้พอบอกว่า "ใช้เมื่อไหร่" แล้วย้ายวิธีทำงานลงไปอยู่ในเนื้อไฟล์
- ใส่ `Bash` ใน `tools` ของนักวิจัย — Bash ทำได้ทุกอย่างรวมถึงเขียนไฟล์ รั้งที่ดีที่สุดของ "คนอ่านอย่างเดียว" จึงรั่วทันทีที่มีตัวนี้
- เชื่อคำว่า "เขียนแล้ว" โดยไม่เปิดไฟล์ด้วยตา — เคยมีรอบทดสอบที่เอเจนต์รายงานว่าเขียนเสร็จทั้งที่ไฟล์ไม่มีอยู่จริง ขั้น `cat` ในลำดับข้างบนจึงไม่ใช่ตัวเลือก
- ตั้ง `--max-turns` ต่ำในการทดสอบ headless — หมดเทิร์นก่อนไฟล์โผล่ จบรอบแบบไม่มีงานให้ตรวจ

<summary>1. ฟิลด์ไหนทำให้ leader ส่งงานให้เอง</summary>

</details>
