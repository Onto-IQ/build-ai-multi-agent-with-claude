# Module 6 — MCP

> ⏱ ~35 นาที · 🎯 ต่อ MCP แบบ stdio เข้า Claude Code แล้วเรียกเครื่องมือด้วยชื่อ `mcp__เซิร์ฟเวอร์__เครื่องมือ` · Connect a local stdio MCP server and call one tool by its full name.

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ถึงตอนนี้เอเจนต์ของเรามีเครื่องมือในตัวครบที่จำเป็น แต่มีของที่มันไม่มี: ข้อมูลที่อยู่นอกโปรเจกต์ หรือโปรแกรมที่คุณเขียนเอง — **MCP (Model Context Protocol)** คือทางต่อของพวกนั้น มันคือข้อตกลงรูปแบบข้อความ (JSON-RPC) ที่ทำให้เอเจนต์เรียกใช้เครื่องมือที่อยู่นอกตัวมันได้เหมือนเครื่องมือในตัว

ในห้องนี้เราใช้ชนิดที่ง่ายที่สุดคือ `stdio` — เซิร์ฟเวอร์ MCP เป็นแค่สคริปต์ Node บนเครื่องเดียวกับ Claude ที่คุยกันผ่านบรรทัดข้อความ ไม่ต้องมีเน็ต ไม่ต้องมีพอร์ต และกฎข้อหนึ่งของมันเข้มงวดมาก: **stdout ของสคริปต์นี้คือสายของโปรโตคอล** — พิมพ์อย่างอื่นลงไปนอก JSON แม้บรรทัดเดียว สายก็พังทันที (ถ้าจะดีบัก ให้พิมพ์ลง stderr)

อีกเรื่องที่มักสับสน: `stdio` คือชนิดของ**สาย** ส่วน `node script.js` คือ**วิธียก**เซิร์ฟเวอร์ขึ้น — อย่าเผลอเขียนสลับกันในไฟล์ตั้งค่า

> EN: Stdio MCP means newline-delimited JSON on stdout. The tool name in Claude is mcp__server__tool.

## Concept / เนื้อหา

ชนิดของสายที่มีให้เลือก (แผ่นอ้างอิง — ห้องนี้ใช้แค่ตัวแรก):

| Transport | ใช้เมื่อ |
|---|---|
| stdio | สคริปต์บนเครื่องเดียวกับ Claude Code |
| HTTP | บริการปลายทาง |
| WebSocket | งานที่เซิร์ฟเวอร์ผลักเหตุการณ์ — ในห้องนี้ไม่ใช้ |

ใน repo มีไฟล์เริ่มต้น `mcp/echo-server.js` พร้อมเครื่องมือ `echo` อยู่แล้ว เวลาเราลงทะเบียนมันกับ Claude ภายใต้ชื่อ `sales-echo` ชื่อเต็มของเครื่องมือในสายตา Claude จะกลายเป็น `mcp__sales-echo__echo` — ชื่อสามส่วนต่อกันด้วยขีดล่างสองตัว: คำนำหน้า `mcp__`, ชื่อที่ตั้งตอน add, แล้วชื่อเครื่องมือ

ขอบเขตการลงทะเบียนมีสามระดับ: `local` (อยู่เครื่องนี้), `project` (อยู่ในไฟล์ `.mcp.json` แชร์กับ repo ได้) และ `user` — และถ้าต้องการผูกเครื่องมือนี้เข้ากับเอเจนต์ตัวใดตัวหนึ่งโดยเฉพาะ ให้ใส่ `mcpServers` ใน frontmatter ของเอเจนต์นั้น

Workshop 3 ทำแค่ต่อสายกับเรียกของที่มีอยู่ตามขั้น ไม่ได้ออกแบบ MCP ใหม่ทั้งระบบ — เฉลยมีเครื่องมือ `lookup_province` กับ `shout` อยู่คนละไฟล์กับ echo เริ่มต้น

## ลงมือทำตามลำดับ

ทุกขั้นทำจากโฟลเดอร์แอป:

```bash
```

1. ลงทะเบียนเซิร์ฟเวอร์ — สังเกต `--` คั่นกลาง มีหน้าที่กัน Claude Code อ่านตัวเลือกของสคริปต์เป็นตัวเลือกของมันเอง:

```bash
claude mcp add sales-echo -- node mcp/echo-server.js
claude mcp list
```

   ผลที่ต้องเห็น: รายการมี `sales-echo`

2. เปิด TUI แล้ววาง prompt จากหัวข้อถัดไป — รอบนี้จะมีกล่องขออนุญาตเครื่องมือ MCP ให้กดเอง (โจทย์ภาษาไทยส่งข้อความไทยปนเลขไทย ตั้งใจให้เห็นว่าตัวอักษรเดินทางไปกลับครบหรือไม่)

3. ผลที่ผ่าน: Claude บอกได้ตรง ๆ ว่าข้อความกลับมาตรงทุกตัวหรือเพี้ยน ถ้าเพี้ยน แปลว่ามีที่ไหนสักแห่งพิมพ์ของแปลกปลอมลง stdout

4. ผูกเครื่องมือนี้เข้ากับ `data-researcher` — เพิ่มใน frontmatter ของไฟล์เอเจนต์:

```yaml
mcpServers: sales-echo
```

## Prompt pattern — เลือกใช้อย่างใดอย่างหนึ่ง

**เวอร์ชันไทย (แนะนำ) — เขียนแบบล็อกค่าพารามิเตอร์:**

```text
เรียกเครื่องมือ mcp__sales-echo__echo หนึ่งครั้ง โดยตั้งค่าพารามิเตอร์ text ให้มีค่าเป็นสตริงต่อไปนี้เป๊ะ ๆ ทุกตัวอักษร ห้ามแก้ ห้ามย่อ ห้ามตัดคำ:

สวัสดี — ทดสอบ ก-ฮ ๐๑๒๓

จากนั้นรายงาน 2 อย่าง: (1) ค่า text ที่คุณส่งไป (2) ข้อความที่เครื่องมือ echo กลับมา แล้วสรุปว่าตรงกันทุกตัวอักษรหรือไม่ รวมถึงเลขไทย ๐๑๒๓
```

**เวอร์ชันอังกฤษ (ใช้ได้เต็มที่):**

```text
Use the sales-echo MCP echo tool with the text "hello-sales" and quote exactly what came back.
```

> 📚 **ทำไมแนะนำ TH:** โจทย์ไทยทดสอบสองชั้นในรอบเดียว — การเรียก tool ปกติ และการเดินทางของตัวอักษรไทย+เลขไทยทั้งสาย (คอร์สทดสอบแล้ว: กลับมาตรงทุกตัว ไม่มี mojibake) ส่วน EN ตรวจได้แค่ชั้นแรก

ทำขั้นเรียกเครื่องมือใน TUI จะกดอนุญาตเครื่องมือ MCP ได้เอง ถ้าต้องใช้ headless จริง ๆ ต้องใส่ชื่อเต็มและจำนวนรอบทำงาน (เทิร์น) เช่น `--allowedTools "mcp__sales-echo__echo" --max-turns 10` — แล็บในห้องใช้ TUI

## Common pitfalls / กับดัก

- ลืม `--` ตอน `claude mcp add` — Claude Code อ่านตัวเลือกของสคริปต์เป็นตัวเลือกของตัวเอง การลงทะเบียนพังตั้งแต่ขั้นแรก
- พิมพ์ข้อความดีบักลง stdout — โปรโตคอลพังทันที ดีบักไปที่ stderr เท่านั้น
- ใช้ชื่อ `echo` ตอนให้สิทธิ์ — ชื่อจริงในระบบคือ `mcp__sales-echo__echo` เต็มสามส่วน
- ทำใน `claude -p` — Bash ที่ใช้ยกเซิร์ฟเวอร์ถูกปฏิเสธ ทำใน TUI
- ตั้ง `--max-turns` ต่ำ — ยังไม่ทันได้ผล echo รอบก็จบ
- echo ไม่ตอบแล้วไปปิดแอป — พอร์ต 3000 ไม่เกี่ยวกับ MCP แบบ stdio เลย อย่าไปแก้ที่ผิด
