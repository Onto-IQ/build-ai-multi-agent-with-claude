# Module 1 — สถาปัตยกรรมเอเจนต์ / Agent architecture

> ⏱ ~45 นาที · 🎯 เลือกได้ว่าเมื่องานควรทำพร้อมกันหรือทำทีละขั้น และรู้ว่าทีมเอเจนต์ใช้ token มากกว่าแชทเดียวประมาณ 15 เท่า · Choose swarm or sequential work, and treat a team as about 15× the tokens of one chat.

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

แชตบอตที่คุณคุ้นเคยตอบแล้วจบ — มันไม่มีมือให้จับอะไร เอเจนต์ต่างออกไปตรงนี้: มันรับโจทย์ วางแผน เลือกเครื่องมือ **รันเครื่องมือจริง อ่านผลจริง** แล้วเอาผลนั้นกลับมาใช้ต่อ จนงานเสร็จแล้วส่งมอบ ความเก่งที่เพิ่มขึ้นไม่ได้มาจาก prompt ที่ยาวขึ้น แต่มาจากวงจร "ลงมือ → อ่านผลจริง → แก้ตามผล" ที่หมุนได้เอง

พอมีวงจรนี้ คำถามถัดมาคือ "จะปล่อยให้มันทำกี่ตัว และทำพร้อมกันได้ไหม" — และคำตอบมีราคากำกับอยู่เสมอ ใน Claude Code มีสามรูปแบบให้เลือก แต่ละแบบกิน token ไม่เท่ากัน ทีมเอเจนต์หลายตัวแพงกว่าการคุย Claude คนเดียวประมาณ **15 เท่า** (ตัวเลขที่ Anthropic สรุปจากระบบวิจัยของเขาเอง) ดังนั้นเกณฑ์ตัดสินจึงเรียบง่าย: งานขั้นถัดไปต้องใช้ผลของขั้นก่อนหน้า → ทำทีละขั้น · งานที่ไม่ต้องรอผลกัน → ทำพร้อมกันได้ · งานเล็ก → ทำคนเดียวถูกที่สุด

> EN: An agent is a tool loop. Parallelize independent reads. Sequence anything that consumes the previous artifact. Budget for about 15× tokens.

## Concept / เนื้อหา

วงจรของเอเจนต์หนึ่งรอบเดินตามนี้:

```text
รับโจทย์ → วางแผน → เลือกเครื่องมือ → รันจริง → อ่านผล → แก้หรือส่งมอบ
```

สามรูปแบบการทำงานในคอร์สนี้ (แผ่นอ้างอิง — เลือกจากงาน ไม่ใช่จากความอยากลอง):

| รูปแบบ | ใช้เมื่อ | ใช้ token (เทียบกัน) |
|---|---|---|
| Subagent | ให้ไปอ่าน/ค้นโค้ด แล้วส่งแค่สรุปกลับมา — กันรายละเอียดยาว ๆ ทำให้แชทหลักยาวเกิน | น้อยที่สุดในสามแบบ |
| Agent Teams | หลายตัวคุยกันได้ มีรายการงานร่วม — ยังเป็น experimental | มาก |
| Background agent | งานยาวที่รันคู่ไป ไม่ต้องรอให้จบก่อนพิมพ์ต่อ | ปานกลาง |

เอเจนต์ย่อยที่มีมาให้พร้อมใช้: `Explore` อ่านอย่างเดียว, `Plan` วางแผนก่อนลงมือ, `general-purpose` แก้ไฟล์ได้

และนี่คือภาพรวมของ swarm ที่ Module 3 จะลงมือจริง:

```text
                    ┌──> งาน A ──┐
Leader แตกงาน ──────┼──> งาน B ──┼──> leader รวมผล
                    └──> งาน C ──┘
```

คำถามตัดสินมีข้อเดียว: **งานขั้นถัดไปต้องใช้ผลของงานขั้นก่อนหน้าหรือไม่** — จากงานจริงในคอร์สนี้:

| สถานการณ์ในคอร์สนี้ | เลือก |
|---|---|
| สำรวจ `server.js`, `sales.csv` และ quality gate พร้อมกัน | Swarm (ขนาน) |
| ออกแบบตัวทำความสะอาด → เขียนโค้ด → รีวิว ทีละขั้น | Sequential (ทีละขั้น) |
| หน้าเว็บกับ API หลังมี PRODUCT-SPEC แล้ว | ขนานได้ |
| แก้บั๊กจุดเดียว ต้องไล่สถานะต่อเนื่อง | อย่าตั้งทีมหลายตัว |

Agent Teams ให้เปิดเฉพาะตอนผู้สอนสาธิต ด้วยตัวแปร `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` — แล็บปกติไม่เปิด

## ลงมือทำตามลำดับ

บทนี้ไม่มีการสร้างอะไร — มีแต่การเห็นวงจรเอเจนต์กับตาตัวเองครั้งแรก

```bash
claude
```

1. วาง prompt จากหัวข้อถัดไป แล้วสังเกตสองอย่าง: เอเจนต์เลือกเปิดไฟล์อะไรเองบ้าง และคำตอบสั้นแค่ไหน
2. ลองถามต่ออีกหนึ่งคำถามที่ต้องอ่านไฟล์ใหม่ — สังเกตว่ามันรันเครื่องมืออีกรอบแล้วอ่านผลจริง ไม่ได้เดาจากความจำ

## Prompt pattern — เลือกใช้อย่างใดอย่างหนึ่ง

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Explore this project for 2 minutes and name the single riskiest file. Under 80 words.
```

**เวอร์ชันไทย (ใช้ได้เต็มที่):**

```text
สำรวจโปรเจกต์นี้ประมาณ 2 นาที แล้วบอกไฟล์เดียวที่เสี่ยงที่สุด พร้อมเหตุผล ไม่เกิน 80 คำ
```

> 📚 **ทำไมแนะนำ EN:** ภาษาของ prompt เป็นตัวกำหนดภาษาของคำตอบ — เริ่มคอร์สด้วยภาษาเดียวกันทั้งห้องทำให้รายงานแรกเทียบกันได้ในการสาธิต และอยู่ภาษาเดียวกับชื่อไฟล์ที่จะถูกอ้างใน Workshop ถัดไป TH ใช้ได้เต็มที่ — ชื่อไฟล์และ endpoint ในคำตอบยังถูกพิมพ์ถูกต้องเสมอ

| ส่วน | หน้าที่ |
|---|---|
| เวลา | กันไม่ให้สำรวจทั้ง repo |
| ไฟล์เดียว | บังคับให้เลือก ไม่ใช่รายการยาว |
| ไม่เกิน 80 คำ | กันรายงานยาวจน leader อ่านไม่ไหว |

## Common pitfalls / กับดัก

- ตั้งทีมหลายตัวกับงานที่ทุกคนต้องเห็นสถานะเดียวกัน — ได้คำตอบไม่ตรงกัน แล้วคุณต้องเป็นคนกลางเอง
- ไม่จำกัดความยาวรายงาน — บทสนทนาหลักเต็มตั้งแต่รอบแรก งานต่อจากนี้ยากขึ้นโดยไม่จำเป็น
- คิดว่าใช้ทีมแล้วคุณภาพดีขึ้นเอง — จำนวนเอเจนต์ไม่ใช่คุณภาพ มันคือ token ที่โตขึ้น ~15 เท่า
- ใช้ `claude -p` ทั้งที่อยากเห็นการกดอนุญาตสิทธิ์ — รอบสาธิตใช้ TUI เพราะมีหน้าจอให้กด
- มี `ANTHROPIC_API_KEY` ค้างในเครื่อง — รอบสาธิตจะถูกคิดเงินแบบจ่ายตามการใช้ แทนบัญชีคลาส
- เปิด `node server.js` ค้างไว้แล้วรัน `node scripts/quality-gate.js` — จะเจอ **port busy** เพราะพอร์ตชนกันเอง ไม่ใช่ gate พัง

## Quick check / ทบทวน

<details>
<summary>1. Tool calling ต่างจากการ copy คำตอบไปวางเองอย่างไร</summary>
เอเจนต์สั่งรันเครื่องมือเอง แล้วเอาผลจริงกลับมาใช้ต่อ (ไม่ใช่แค่พิมพ์คำตอบจากความจำ)
</details>

<details>
<summary>2. งานแบบไหนที่ตั้งทีมแล้วไม่คุ้ม</summary>
งานเล็ก หรืองานที่ทุกขั้นต้องเห็นสถานะเดียวกันตลอด
</details>

<details>
<summary>3. ตัวเลข ~15 เท่า ใช้ตัดสินอะไร</summary>
ใช้ตัดสินว่าควรตั้งทีมหลายตัวหรือไม่ — เร็วหรือครบพอที่จะยอมจ่าย token มากกว่าแชทเดียว ~15 เท่า
</details>
