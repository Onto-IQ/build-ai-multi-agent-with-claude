# run-012 — Thai Prompt กำกวม: พฤติกรรมเมื่อโจทย์ไม่มีสเปก (คู่เทียบ run-003)

- **Module/Workshop:** Module 4 / Workshop 2 — เกณฑ์ B1–B3 (ทดสอบ **prompt กำกวมภาษาไทย** — กรณีศึกษาเชิงลบที่ตั้งใจ)
- **เวลา:** 2026-09-29T05:00+07:00 | **Claude Code:** 2.1.284 | **โหมด:** headless `-p --permission-mode acceptEdits --max-turns 8`
- **Working dir:** `labs-sandbox/demo-shop`

- **Prompt ที่ส่ง (ตั้งใจกำกวม — ไม่ระบุชื่อ agent, หน้าที่, ฟิลด์, path):**

```text
สร้าง subagent ให้โปรเจกต์นี้หน่อย แบบที่ใช้งานได้เลย
```

- **ผลลัพธ์จริง:**

```text
Error: Reached max turns (8)
```

- หมดเทิร์นทั้ง 8 โดย**ไม่มีข้อความตอบกลับและไม่มีไฟล์ agent ใหม่** (`.claude/agents/` มีแค่ code-researcher.md + product-writer.md จาก run ก่อน ๆ — ยืนยันด้วย `ls`)

- **ข้อสังเกต (ประสบการณ์ที่เขียนลงสื่อ):**
  1. **ความกำกวม + เพดาน turn ต่ำ = ล้มเหลวเงียบที่สุด** — ต่างจากเคส EN ใน run-003 (iteration 2) ที่ Agent ถามกลับให้ชัด ครั้งนี้มัน "พยายามเดาเอง" (อ่านโปรเจกต์/ตัดสินใจหน้าที่/ลองเขียน) จนเทิร์นหมดโดยไม่ส่งมอบอะไรเลย
  2. เทียบตรงกับ run-009: prompt ไทยที่**ระบุครบ** (ชื่อ, หน้าที่, ฟิลด์, path, "ห้ามถาม") สำเร็จรอบเดียว — ปัญหาไม่ใช่ภาษา แต่เป็น**ความครบถ้วนของสเปกใน prompt**
  3. ประโยค "แบบที่ใช้งานได้เลย" ไม่ใช่ spec — มันคือความหวัง ไม่ใช่ข้อกำหนด (สอนผู้เรียนจำประโยคนี้ได้)
  4. บทเรียนต่อเนื่องจาก run-006: `--max-turns` เป็นดาบสองคม — ต่ำเกินไปกับโจทย์กำกวม = ล้มเหลวโดยไม่มี feedback ให้แก้
- **สรุป:** **FAIL ตามดีไซน์ (instructive failure)** — ใช้เป็น "กรณีศึกษาก่อน-หลัง" ใน M4: prompt กำกวม (run-012) vs prompt ครบสเปก (run-009)
